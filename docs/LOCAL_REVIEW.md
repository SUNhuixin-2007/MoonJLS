## 已修复的问题

| 问题与触发条件 | 修复及验证 |
| --- | --- |
| 放宽 Limits 后，16 位超宽像素行的字节数可在 Int32 中溢出，packed_size 可能返回负数 | Int64 计算并检查预算后才缩回 Int；测试只计算尺寸，不申请巨型图像 |
| encode / encode_rows / RowEncoder 未预检必需标记数 | 统一编码预算检查，预算不足时拉取行与输出回调均不执行；同时测试恰好足额的预算 |
| 扫描内 RST 未计入段数，分段解析可能建立超出该预算的数组 | inspect 扫描熵区时累计 RST；重启编码预检总标记数，避免先编码后超限 |
| HP 编码没有把新增 mrfx 的段数和 5 字节 payload 完整纳入预算 | 与普通编码使用同一预算口径，保留必要变换信息且拒绝超限 |
| PNM 整图解析未将 MAXVAL 后的 LF/CRLF 算全，按行写出漏检头部预算 | 统一完整头部边界，长注释及时受限，预算不足时不调用输出回调 |
| PNM 写出可生成 65536 宽图像，两个读取接口却仍按 65535 截止 | 与 Frame 的受检 Int 尺寸一致；新增 8/16 位超宽 PNM → JLS → PNM 真实文件精确往返 |
| PnmSource 未检查原始输入字节预算，行字节缩回 Int 前也未单独检查 | 校验从 start 到文件尾的输入规模，UInt64 偏移保留，行字节用 Int64 检查 |
| inspect 使用扩大预算后，Info.to_json 对 SPIFF 又使用默认预算 | 新增可选 limits 参数并贯穿 SPIFF 校验，不改变原有默认调用方式 |

原有 31 项测试均能通过时，这 8 组新回归在修复前失败，说明单看旧测试全绿不能覆盖这些边界。修复后它们与补充的预算正例、长注释及全位置逐位变异检查一起通过。
