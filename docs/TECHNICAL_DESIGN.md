# 技术路线

## 先确定码流与图像语义

当前图像模型保留宽、高、2–16 位精度、1–4 个同尺寸分量和无符号整数样本。API 统一为逐行像素交织，编码流的 none/line/sample 交织是独立参数。精度 P 是载体位数，实际 MAXVAL 可为 1…`2^P−1`；样本范围和预测重建按实际 MAXVAL 处理。尺寸计算先按预算除法检查，再计算乘积，不让畸形宽高触发有符号溢出或巨量分配。

容器按 JPEG marker 分离 SOI、SOF55、LSE、SOS、EOI。每段长度先检查，未知但允许保留的元数据也受总预算限制。熵编码段不能沿用普通 JPEG 的字节填充规则：JPEG-LS 在 `0xff` 后保留一个零位，后续字节只贡献七位；结束对齐和标记探测必须与这个规则一致。

## regular 模式为何能够重建

对当前样本使用已经重建的左、上、左上、右上邻居。先计算三个梯度，按 NEAR 和 T1/T2/T3 量化，再进行符号归一得到上下文索引；由邻域中值预测值结合上下文 C 校正得到预测。编码误差经过 NEAR 量化、有限 RANGE 归约和有符号映射，使用当前 A/N 决定的 Golomb 参数编码。

解码器从同一状态恢复误差，再按符号、NEAR 和 MAXVAL 重建样本。A/B/C/N 的更新顺序、RESET 时机、负数右移和偏差限幅必须与编码器一致。近无损编码器也必须使用自己的重建样本更新后续邻域；若错误地使用原始图像，编码器与解码器会在某个样本后失去同步。

## run 模式不是简单的零值压缩

量化梯度全零时，当前行可以编码与左邻值相近的一段 run。run 长度的编码由 run index 与标准 J 表控制，碰到行尾和 run interruption 的处理不同。中断样本根据邻域关系选择两个专用上下文之一，使用独立的 N/Nn/A 统计和映射恢复误差。样本交织还需要多分量统一判定 run；行交织保留各分量所需的 run index。

因此不能用“预测差值加一个通用压缩器”代替 JPEG-LS，也不能把随意实现的 run-length 字节序列称为兼容码流。

## 数值边界与复杂度

全部像素为整数，16 位样本仍可在 Int32 中安全表达，但中间状态增长、移位和输出大小必须受限。NEAR 的有效范围为 `0…min(255, floor(MAXVAL/2))`；显式 preset 必须满足标准阈值顺序和 RESET 约束，零参数按规范采用默认值。默认阈值在扫描使用时按实际 MAXVAL/NEAR 确定。越界、截断和未知功能返回带偏移的错误。

依照 T.87 §A.2.1/§B.2，`RANGE = floor((MAXVAL + 2·NEAR)/(2·NEAR + 1)) + 1`，`qbpp = ceil(log2(RANGE))`，`bpp = max(2, ceil(log2(MAXVAL + 1)))`，`LIMIT = 2·(bpp + max(8,bpp))`。这些数值不能直接套用 P：MAXVAL=1 的 bpp 仍为 2，MAXVAL 为 2 的幂时也必须保留公式中的 `+1`。重建先在 RANGE 域归约，再按实际上下界处理；非满范围不能用 `& MAXVAL` 代替数值限幅。

核心扫描时间与样本数线性相关，状态量为固定上下文表与行缓冲。完整 `Image` API 会物化全部样本。`encode_rows` 从稳定的行源提取所需分量，none 可回访原始行；`decode_rows` 只保留两个重建行，但压缩输入仍驻留。`RowEncoder.push` 接受一个完整像素行，立刻排出已完成的物理字节；BitWriter.take 保留部分字节、FF 后的七位容量及累计字节预算。它只接受灰度 none 和彩色 line/sample，多扫描 none 使用 pull 接口。

行回调收到独立数组，后续解码不会改写已交付的行；回调失败、行宽或样本非法、提前 finish 都使推送编码器进入不可继续状态。最后不足字节的零填充与 EOI 只在成功 finish 时写出。核心不承诺文件事务，Node 宿主用独占创建、成功后同步、失败删除本次新建文件来实现可检查的落盘语义。

## 独立验证如何区分保证

独立编码 → MoonJLS 解码，与参考实现的重建数组逐样本比较；MoonJLS 编码 → 独立解码，再与 MoonJLS 自身解码结果比较。NEAR=0 要求重建值完全等于输入；NEAR>0 除最大绝对样本误差不超过 NEAR，还检查参考重建值一致性。编码字节可因合法标记和编码选择不同而不同，不能把压缩字节不一致直接认定为失败。

证据分开记录：原 imagecodecs/CharLS 282 组双向和 80 组扩展用例覆盖满范围配置；本轮新增官方 T.87 参考程序的 144 组输入和 144 组输出验证，覆盖合成灰度图的非满范围配置。参考 EXE 不接受 MAXVAL=1/2，这两点由独立的规范手推向量补充；低 MAXVAL 近无损用例对旧参考程序显式设置合法阈值/RESET，不能把旧版默认阈值当作最终规范。MAXVAL=1000、NEAR=0/3 的双向实际文件与结果见 [MAXVAL_EVIDENCE.md](MAXVAL_EVIDENCE.md)。这些证据并不覆盖所有分量、变换和语法组合。

平坦图、长 run、行边界、交替极值、不同位深、多个分量和确定性随机图覆盖不同状态路径。边界测试还应独立覆盖每个截断点、非法 preset、压缩数据中伪标记、输出预算与元数据预算。自测往返和检查图片能打开都不足以证明与外部工具互操作。

## 部署边界

核心为纯 MoonBit；PNM/JSON 与宿主文件工具是消费者，不是算法替身。实际部署是否支持一个交织、重启或颜色变换特性，以功能矩阵与交叉验证为准。未支持项必须拒绝，不能忽略标志后输出看似合理的错误像素。

## 重启、容器扩展与消费者

T.87 §B.3 的重启间隔单位是 MCU。当前只支持同尺寸 Hi=Vi=1 分量，此时按行推进，DRI 仅实现 16 位值。编码器在分段边界结束零填充、写循环 RST 编号，再清空上下文和上行；解码器先识别并校验 RST 序号和分段数，对每段独立恢复预测状态。边界判断同时处理 marker fill 与 JPEG-LS 零位填充，不能照普通 JPEG 的字节填充处理。最终基线实现还要处理异采样 line 模式的 Vi 行组与底部补齐，并补齐 24/32 位 DRI 及 DNL，不能把当前行实现泛化为全部 MCU 语义。

SPIFF 标头与 EOD 是非强制 APP8 包装；其 frame 必须与 SOF55 一致。HP 颜色变换是 CharLS 附加扩展，在整数模域中进行，只有 lossless RGB 8/16 位路径被接受；剥除非必要元数据必须保留 mrfx，否则解码出的 RGB 会错误。LSE4 大尺寸在原 T.87 §C.2.4.1.4 中已属于 Part 1：当前写入四字节字段，读取接受 2/3/4 字节字段，乘法分配前仍检查 Limits。其在 SOF55 前出现、零高度延迟定义及第一扫描后的 DNL 尚未完整实现，不能因已有超宽图用例就认为尺寸语法全部完成。

文件入口的 ByteSource 用 UInt64 表达偏移，宿主必须返回精确长度。PnmSource 只缓存有界头部并按行读 binary P5/P6，大端 16 位样本由 MoonBit 解包。PAM P7 补充灰度 Alpha/RGBA 原始交换，ENDHDR 后的空白和 # 是像素而非注释。Node 只负责范围 I/O，不实现预测、熵编码或 JPEG-LS 字段解析。

ROI 接口遵循预测依赖，解码所有扫描但只保存选区；预算选择也只比较实际编码结果。`encode_to_budget` 限定候选 NEAR/交织、尝试次数及处理样本总数，以实测最大误差、MSE、字节数排序；返回 None 仅说明给定候选未满足字节目标，不声称不存在其他编码方法。

## 最终基线目标如何落到接口和验收

v0.1.x 的满范围 MAXVAL 守卫是建立首批互操作证据时的阶段限制，不是标准边界。本轮计划版本 0.2.0 已补入非满范围处理和上述独立验证，编码保留实际 MAXVAL，不通过改成满范围绕过问题。当前实现仍未达到完整基线符合性；最终目标和逐项状态见 [BASELINE_PLAN.md](BASELINE_PLAN.md)。

异采样需要新增各分量独立的 Plane 模型，按 Hi/Vi 推导尺寸及扫描行序，现有同尺寸 Image 保留为便捷接口。映射表需要表达任意 Wt 字节输出，不能塞回一个整数像素；解码器还需保存 table-only 数据并供 abbreviated image 使用。point transform 要区分编码域和逆变换输出域，并校验其与映射表互斥，不能将编码域的 NEAR 直接描述为任意变换后输出的误差界。上述功能以及 DNL、宽 DRI、完整尺寸语法均为后续基线任务，Part 2 另列范围。

最终验收以 [ITU 官方 T.87](https://www.itu.int/rec/T-REC-T.87-199806-I/en) 第 8 章及 Annex E 全 12 组为起点，另加其未充分覆盖的映射/Pt、缩略格式、非满 MAXVAL、重启和标记语法矩阵。第 7/8 组包含异采样，当前不可略去后宣称全通过；最小官方图集或任一参考实现互通也不能单独证明全部标准语义。官方参考软件及图集只按其测试许可使用，放在忽略的工作目录，不并入 BSD 产品代码分发。
